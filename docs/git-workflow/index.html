Git workflow

Back to the overview

Linked worktrees, one delivery path to the mainline and main checkout sync, configured by [git]. Run several agents shows how it fits with sessions; the other tables are in the pmcp.toml reference.

Tracked files they rewrote also get their index mode back (0644, or 0755 for executables); untracked files are never touched.

[git.shared_checkout] warns a session working in the main checkout of a repository that also has linked worktrees, tracks the files it edits there, and names leftovers not yet delivered, because they block syncing the shared main for everyone. Keys: enabled ("auto" default, following [git] enabled, or a boolean), warn_on_session, track_edits, warn_claimants (booleans, default true). It is on in any git checkout without a table, once something else enables the hook bundle.

[git.worktrees.sync] (opt-in) keeps each linked worktree on the mainline when moving it loses nothing: on_session_start ("fetch_and_move" default, "move", "off"), between_prompts ("move_if_light" default, "off": move only when no install is needed), install_after_move ("off" default, "background", "foreground") and notice_paths (paths whose change is announced to the session). Installs never block a session.

[git.mainline.gate]: command (argv; no gate when missing), tree (the gate's worktree, default <state dir>/gate/tree; a relative path is relative to the main checkout, like state_dir), lock_wait_seconds (default 5400), lock_env (an environment variable name), tree_env (an environment variable name) and log_dir (default <dir of tree>/logs). Each gate's full output goes to <log_dir>/<UTC time>-<tip>.log as well as the terminal; pmcp names the file when the gate starts and again if it fails, and keeps the newest 20. With max_load (the 1-minute load average, e.g. 6) a delivery that holds the lock waits until the load is below it before the gate starts, checking every 15 seconds for up to load_wait_seconds (default 1800), and then fails without running the gate; once started, a gate is never retried.

One delivery gates at a time: pmcp takes an exclusive flock on the file lock beside the gate tree (<dir of tree>/lock), so another tool that takes the same file with flock (a workspace land script) and pmcp never gate together. With lock_env set, pmcp sets that variable to 1 for the gate command and its children, and a pmcp git deliver started with it already 1 runs under its caller's lock instead of waiting for it. tree_env names a variable that, when set, gives the gate tree instead of tree, and so moves the lock and every ${gate_dir}/ path with it (a temporary gate for tests or a bootstrap). While a delivery holds the lock it keeps holder.json beside it, {tip, subject, checkout, pid, startedAt}, so a tool waiting on the same lock can say whose gate it waits for; the file is removed on release.

A lease is <state dir>/<name>-lease.json unless [sessions.leases.<name>] file places it elsewhere, for another tool that coordinates the same lockfile; both read and write {pid, subject, cwd, since}, and a record whose process is gone counts as free. With events set, each delivery that changed the leased paths appends one line there: {at, subject, commit, hash, installed, lease}, where commit is the delivered upstream, hash the leased files' hash in the main checkout after sync, and installed whether sync's install ran for that hash.

[git.mainline.deliver] enables pmcp git deliver, which replays commits onto the fetched mainline, runs the gate, and pushes one delivery at a time: attempts (default 3), refuse_direct_push (default true: a hook refuses git push from any checkout of this repository, so the mainline moves only through delivery), during_pause ("refuse" default or "allow"), lease_wait_seconds (default 3600) and notify (argv run after a delivery).

pmcp git deliver --json prints one receipt on stdout when it ends, progress staying on stderr: {ok, code, delivered, upstream, attempts, gate, leases, reason?}, where delivered is the upstream commit it pushed (or null), gate is {exit, log} for the last gate run (or null), leases the leases it took and reason the last refusal or failure. Exit codes: 0 delivered or nothing to deliver; 1 refused, a lease or the gate lock held too long, a replay conflict, the gate failed, the push failed or it gave up after attempts; 2 fetch failed or no configuration.

[git.mainline.sync] enables pmcp git sync, which moves the main checkout to the mainline: install (argv), install_when_changed (paths; when no [sessions.leases] are declared, these become an implicit lockfile lease), keep_identical_files and refuse_with_unlanded (booleans, default true).

After a successful install, sync records the hash it installed in a stamp and installs again only when that hash changes. By default the stamp is pmcp's own, in its state directory. stamp puts it at a path another tool also reads (${git_dir}/name is in the checkout's own git directory, so each worktree has one; ~/ and absolute paths work too). stamp_hash = "plain" makes the hash the sha256 of the single install_when_changed file's bytes, which other tools can compute and write themselves; the default "pmcp" hashes every listed path with its name. Delivery events record the same hash and whether the stamp matches it.

[git.submodules]: follow = "clean_pins" (the default when the table is present) moves submodules to the pinned commit when they are clean; "off" leaves them. Without the table submodules are not followed. shared lists submodules other sessions also edit in the main checkout (a brand app, for example): those move to the new pin even with uncommitted edits, as long as no edited or untracked file is one the pin changes. When one is, the submodule stays on the old pin and sync names the files; pmcp never restores, stashes or discards them.

With push = "pins", pmcp git deliver first makes sure every submodule commit the delivered commits pin is on that submodule's origin. A pin already on a remote branch needs nothing. Otherwise exactly the pinned commit is pushed to the submodule's branch (branch in .gitmodules, else main) as a fast-forward, never a later commit; if that branch has moved past the pin's base, delivery stops before anything else moves.
